# Content, hierarchy, feedback, and preferences

Read for substantial UI work. Preserve required content; obtain agreement before removing supplied material.

## Preferences and content

Record audience, primary task, desired density, liked references and reasons, disliked patterns, brand constraints, and motion tolerance in the project's creative direction brief. Inspect existing conventions first. Label assumptions. A restrained interface without a named style is a valid direction.

For every section identify the user question answered, essential evidence, next action, and reason for its position. Merge repeated claims; shorten paragraphs that impede scanning. Use disclosure for optional detail, never essential pricing, consent, errors, or instructions. Do not invent testimonials or proof.

Give each decision region one visually dominant action by default and quieter secondary links. Document exceptions for comparison tasks or equally important choices. Count competing emphasis rather than every toolbar button; dense professional tools need different rules from landing pages.

Compose mobile deliberately. Preserve essential content and reading order while simplifying decoration. Replace repeated cards with lists or tables when that better represents the information.

## Interaction coverage

For each component mark applicable states: default, hover, focus-visible, pressed, selected, disabled, pending, success, error, empty. Specify trigger, feedback, interruption/recovery, and reduced-motion behavior. Essential actions must work without hover.

Use micro-animation to clarify change and provide feedback. Keep responses immediate, prevent accidental duplicate submissions, cancel obsolete transitions, and clean up listeners. Reduced motion retains understandable state changes. Avoid gratuitous motion or scroll interception.

## Illustrative critique examples

| Problem | Candidate correction | Verification |
|---|---|---|
| Three paragraphs repeat the hero promise | Keep one explanation; place necessary specifics near decisions | Product, audience, and next step are clear |
| Every card has a filled CTA | Reduce secondary emphasis | Navigation remains discoverable by keyboard and touch |
| Submission has no feedback | Add pending, success, and recoverable error states | Exercise slow success and failure |
| Desktop cards make a long mobile stack | Use compact lists or appropriate disclosure | Required information stays available |

These are illustrative examples, not measured benchmark results. Critique actual screenshots for alignment, type hierarchy, spacing, and contrast; record findings, corrections, and unresolved tradeoffs. If no defect is found, report that rather than inventing a correction.

## Feedback loop

Keep project design notes with user correction, reason, change, and verification. Reuse agreed preferences on subsequent tasks. Do not turn a single experiment into a global preference or silently create global memory.
